# 玄墟小说项目

状态：v0.2 项目工程化初始化

这是一个长期小说项目仓库，用于维护世界观、人物、修行体系、剧情章纲、正文草稿、术语库、决策日志和废案记录。

## 项目定位

长篇玄幻修仙为主，科幻悬疑作为骨架、质感和解释层。

地球与修真界是相互独立的两个世界。地球可以极其特殊，但不是修真界的附属、分支或下位世界。

## 当前核心原则

- 修仙是主线，科幻是谜团、认知方式和底层机制。
- 开局写现实世界，但不能拖成长期地球科研篇。
- 第一卷写到修仙刚起步。
- 江彻是核心主角，但队友可以在必要场景拥有高光视角。
- 避免过度分流：队伍可以长期离队，但叙事重心不能散。
- 后宫可以有，但不是主要剧情，不写成感情收集。
- 核心队友不允许廉价背叛；若有伪背叛或被迫站到对立面，必须服务更强剧情。
- 核心队友只能在大后期死亡，而且死亡必须具备整部书级别的情感和局势重量。
- 旧上传文档只作为早期样本，不再作为准设定；本仓库从 v0.2 起成为权威设定源。

## 仓库结构

- `00_项目管理/`：创作宪章、决策日志、版本规则、待定问题。
- `01_世界观/`：地球、修真界、玄墟、界痕、飞船事故、高层秩序。
- `02_人物/`：主角团、人物接口、本土人物、感情线原则。
- `03_修行体系/`：境界体系、突破写法、科学解释边界。
- `04_剧情/`：全书结构、分卷章纲、长线伏笔、终局方向。
- `05_势力与经济/`：坊市、宗门、商会、灵石、林序搞钱线。
- `06_正文草稿/`：正式章节草稿。
- `07_资料库/`：名字、术语、地名、灵感碎片。
- `99_废案/`：已否决或已覆盖设定。

## 工作方式

所有重大设定调整必须进入对应文档，并在 `00_项目管理/01_决策日志.md` 记录原因。聊天中的临时想法不自动成为定稿，只有进入仓库的内容才视为项目准设定。
